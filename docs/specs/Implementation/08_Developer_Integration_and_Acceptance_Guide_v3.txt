01. Developer scope and working agreements
Build one secure, mobile-capable management platform with seven domain modules plus common portals. Distinct 
project modules are joined by canonical project identifiers, signed approvals, event history and independent role 
permissions. Module 7 supplies common services continuously; do not build it as a project step that starts only after 
construction.
 Deliver responsive employee (including low-bandwidth skilled worker), supervisor, PM, department, GM, 
protected auditor, owner, subcontractor, supplier and client role experiences.
 Use strong authentication/MFA for approvals/payee changes and protected audit; role-based plus project-scoped 
authorization validated on server.
 Never silently edit original submitted evidence. Expose corrected/reviewed versions and preserve immutable 
original to authorized auditors.
 Treat permission, contract, statutory, financial and safety gates as server-side invariants, not only disabled 
browser buttons.
 Provide API docs, tests, migrations, backups, staging deployments, source ownership handover and staff 
training.

05. End-to-end integration sequence
 Enquiry -> confirmed visit -> project ID -> mobile original survey -> generated site report -> architect 
review/assign -> Module 2.
 Architectural 2D -> client versioned approval -> 3D -> structural -> mechanical/plumbing -> electrical -> QS -> 
proposal snapshot.
 Management-approved publication -> client portal/physical approval -> management verifies -> Accounts checks 
milestone -> separate Module 4 release.
 Applications and professional certification -> corrections/version control -> conditional planning approval -> 
contracted service choice and sign.
 Executed contract -> PM appointed -> planning-only construction -> Accounts and Compliance readiness -> 
manager physical mobilization authorization.
 Worker tasks and originals -> supervisor verification -> PM analysis and authorized client publication; store and 
asset events link project cost.
 Procurement approved PO -> supplier -> actual accepted GRN -> match invoicing -> independent authorized 
payment and Accounts reconciliation.
 Safety / quality / statutory hold -> independent qualified review -> documented clearance -> authorized affected 
work release.
 Variations / milestone billing / time impacts -> QS/Contracts/Accounts -> management approved client terms and 
signature.
 Practical completion -> separate handover, financial final account, retention, defects, warranty case and final 
closure.
06. Non-negotiable business invariants
 Platform owner must not inherit unrestricted superuser audit data or daily operational approvals just because 
they own shares.
 GM and departmental managers cannot unilaterally alter independent whistleblower evidence or audit case 
attribution.
 No automated arrears reminders: Accounts must explicitly initiate and log each client payment reminder.
 No construction use of expired/unsafe asset, unqualified operator, statutory noncompliant site or professionally 
uncleared structural stage.
 Financial exceptions only affect eligible financial gate and retain actual balance; they never forgive debt or 
override statute.
 Never issue a purchase order from a request alone. Supplier evaluation, commitments, management 
authorization and PO remain separate.
 Never pay changed supplier bank/M-Pesa details until independent out-of-band trusted-contact verification and 
reauthorization.
 No wage deduction as an automatic variance/loss response; all responsibility decisions require fair and lawful 
procedure.
 Advance accounting impairment differs from legal waiver or debt extinguishment; audit both.
 Opening Module 7 controls does not automatically activate a project stage; service scope per client contract is 
authoritative.

08. Non-functional requirements and evidence
 Supported use: responsive browser for operations; low-bandwidth mobile employee capture with offline queue 
and explicit sync acknowledgment.
 Availability and recovery targets must be separately approved; implement encrypted offsite backups, restore 
exercises, encrypted transport, confidentiality and disaster recovery.
 Use queue-based resilient notifications; if WhatsApp/TikTok/Facebook/YouTube integration is not 
approved/available, fall back to staff task queue instead of pretending messages were sent.
 Create staging test users for Owner, GM, acting GM, HR, Accounts requester/payee verifier/payer/reconciler, QS, 
Architects, PM, supervisors, workers, subcontractors, auditors and clients.
 Provide documented role matrix, threat model, professional legal regulatory checklist, event-to-record 
traceability, audit retention and case confidentiality proofs.
 Write automatic tests for every table row above, show evidence screenshots and the underlying exact records in 
demonstrations, and obtain signed acceptance per delivery wave.
